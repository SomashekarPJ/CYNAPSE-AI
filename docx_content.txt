02 · YOUR 3 FEATURES — BACKEND LOGIC
FEATURE A — Phishing Site Visual Clone Detector
The backend captures a screenshot of the suspicious URL using a headless browser, extracts a visual hash, and compares it against a curated database of legitimate banking and government site fingerprints. A second layer uses Groq to analyse any text extracted from the page for phishing indicators.

ENDPOINT:   POST  /analyze/visual-clone
INPUT:      { url: string }
OUTPUT:     { similarity_score: int (0-100), verdict: string,
              matched_site: string, risk_factors: list, screenshot_url: string }

Logic you need to implement (from scratch):
Use Playwright or Selenium to render the suspicious URL in a headless browser and capture screenshot
Extract perceptual hash (pHash) of the screenshot using imagehash Python library
Compare pHash against your pre-built fingerprint DB of top 30 Indian banking/govt sites
Calculate Hamming distance between hashes — convert to 0–100 similarity score
Layer 2: extract all visible text from page using BeautifulSoup + run Groq analysis
Combine visual score + text analysis score into final weighted verdict
Store result in PostgreSQL threats table. Broadcast to WebSocket channel.

FEATURE B — AI Chatbot Impersonation Detector
The backend analyses a conversation transcript for statistical and linguistic signals that distinguish human writing from AI-generated responses. It checks for templated opening phrases, unnatural consistency in response length, absence of genuine contextual memory across turns, and overuse of formal phrasing patterns.

ENDPOINT:   POST  /analyze/chatbot
INPUT:      { conversation: string }
OUTPUT:     { bot_probability: int (0-100), verdict: string,
              evidence: [ { signal: string, explanation: string } ] }

Logic you need to implement (from scratch):
Split conversation into turns and label each as [THEM] or [YOU]
Extract [THEM] turns only — these are the suspected bot responses to analyse
Run Groq LLM analysis with a carefully designed prompt: ask it to identify bot-like patterns
Separately run pattern matching: check for templated phrases, response length variance, formality score
Score each signal 0–1 and weight them into a final bot_probability score
Return evidence list: top 5 signals with plain-English explanation for each
Log to PostgreSQL. No user data retained — store only the analysis output.

FEATURE C — Pre-Transfer Shield
The backend validates a payment recipient identifier (UPI VPA, phone number, or bank account) against a scam registry, checks VPA pattern against known fraud templates, assesses account age via available signals, and returns a 0–100 risk score with specific risk factors.

ENDPOINT:   POST  /analyze/pre-transfer
INPUT:      { type: 'upi'|'phone'|'account', value: string, amount: int }
OUTPUT:     { risk_score: int (0-100), verdict: string,
              risk_factors: list[string], recommendation: string }

Logic you need to implement (from scratch):
Validate input format: UPI VPA regex, phone number format (10-digit Indian), bank account pattern
Check against your scam registry (a JSON file you build with known fraudulent patterns)
For UPI VPAs: score the @handle domain (suspicious handles like @ybl-new, @ibl-pay, etc.)
Run Groq analysis on the VPA/phone against known scam patterns in your Indian fraud database
Check if amount is a round-number above ₹5000 (common in advance-fee fraud)
Combine all signals into a weighted 0–100 risk score
Return risk_factors list explaining each red flag in plain English

06 · DATABASE SCHEMA — POSTGRESQL
CREATE TABLE threats (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    feature      VARCHAR(30),    -- 'visual_clone' | 'chatbot' | 'pre_transfer'
    input_hash   VARCHAR(64),    -- SHA-256 of input (no raw user data stored)
    verdict      VARCHAR(20),    -- 'SAFE' | 'SUSPICIOUS' | 'CRITICAL'
    risk_score   INTEGER,        -- 0 to 100
    evidence     JSONB,          -- { signals: [...], factors: [...] }
    created_at   TIMESTAMP DEFAULT NOW()
);

-- No personal user data is stored. Only anonymised analysis outputs.
